# X-Ray Spec

A hosted, single-tenant, per-user patent **specification viewer**: upload or fetch a US patent (grant or application), extract and read the specification beside a synchronized source PDF, and cite it with printed `column:line` (grants) or paragraph (`[0042]`, applications) references. Textual `FIG. 12A` references and component reference numerals (`housing 104`) link to evidence-backed regions and exact callout boxes in the drawings.

This is a **ground-up rebuild** of an earlier Flask prototype. The extraction engine is re-implemented clean-room in a deterministic, geometry-anchored paradigm — no prototype code is reused. The full design is in **[DESIGN.md](DESIGN.md)**; this README is the map from that document to the code.

## Status

**Phases 1–2 complete; Phase 3 (clean-room extraction) in progress.** On top of the Phase −1 scaffold:

- §7 ORM models (User, SourceDocument, UserDocument, ExtractionArtifact, Bookmark, Annotation, AuditEvent) — `backend/app/db/models.py`
- Supabase JWT verification + email allowlist + local-user upsert — `backend/app/auth`, `backend/app/api/deps.py`
- Documents + bookmarks API with an **owner predicate on every query** and audit events — `backend/app/api/v1/documents.py`
- Async Alembic environment wired to the models — `backend/migrations/env.py`
- **Direct-upload ingestion** (§11.1): `POST /uploads` grant → browser PUT → `POST /uploads/{id}/complete` finalize (server-observed size/SHA-256/magic bytes, **no PDF parsing in the web tier**) → source/user document + queued extraction job. Storage is an interface with a Supabase impl and an in-memory impl for tests — `backend/app/storage/`, `backend/app/api/v1/uploads.py`
- **Fetch by identifier** (§11.2, §7.2): a deterministic structured patent parser (grants `B1`/`B2`/`A` **and** applications `A1`/`A2`, with ambiguous/unsupported input rejected as a validation choice) wired into `POST /documents` (fetch), which creates the source and queues a `fetching_source` job for the egress worker — `backend/app/patents/`
- **Portable import** (§11.3): a bounded, untrusted-input validator/migrator (`app/imports/`) — byte/depth/entry/bookmark/string limits, typed-locator + normalized-box validation, **v1→v2 migration**, and regeneration of all file IDs/keys — behind `POST /imports` (analyze in quarantine) → `POST /imports/{id}/commit` (explicit migration confirmation → `imported_unverified`, text-only document + immutable artifact + bookmarks). Server-side `write` added to the storage interface.
- **Deletion workflow** (§9.4): DELETE revokes access synchronously, then an **idempotent purge** (`app/services/deletion.py`) removes bookmarks, annotations, jobs, immutable artifacts (+ their blobs), and the source PDF + row (when unshared), leaving a content-free audit tombstone. Safe to retry to completion.
- **Documents view + Viewer** (frontend, §16.1, §16.4): React + TS SPA — sign-in, documents list (state badges, Open, delete) with a **live SSE progress bar** per active job (stage label + determinate/indeterminate percentage streamed from `GET /jobs/{id}/events` over a `fetch`+`ReadableStream` reader that carries the bearer token and resumes on `Last-Event-ID`; the row flips to ready on the terminal event), ingestion tabs (fetch / upload / import), and a **reading Viewer** with **modular panes (Text / PDF / Split / Details)**. The text pane renders the specification with `col:line`/paragraph refs, per-line confidence dots, and **inline figure/reference-numeral highlights** (colored by association status). The **PDF pane** (PDF.js) renders the source page with an **overlay + selectable text layer positioned from each line's box** — so text can be selected on the page (working for scanned patents too) and copied with a citation; clicking a text line jumps the PDF to that line. A shared **citation bar** (Copy text / citation / text + citation, single-line or range) works from either pane, with **configurable citation profiles** (presets + toggles, live preview, persisted). **Phase-4 completion** (§16, `frontend/src/spec/`): in-spec **search** (highlight, next/prev, scoped to all / claims / figures), an **Outline** pane (sections + figures + bookmarks + notes with jump), **shareable deep links** (`#doc=…&line=…` restore the document at a line), **keyboard navigation**, server-persisted **bookmarks + annotations** (owner-scoped API), **callout overlays** on the drawing with **forward/reverse cross-navigation** (numeral → its callout, callout → cycle its mentions) and an **ambiguity chooser** (never a silent guess), **PDF rotation**, a **quality/provenance** surface (warnings banner + alignment-correction markers), and **portable exports** (re-importable JSON + plain text). Pure `spec/` modules are covered by **Vitest** (27 tests). Served by the artifact API (`GET /artifacts/{id}`, `/entries`) and authorized PDF delivery (`GET /documents/{id}/source.pdf`) — `frontend/src/`, `backend/app/api/v1/`
- **Job execution engine** (Phase 2, §10): the durable async spine — a portable Postgres-queue claim (`SKIP LOCKED` on Postgres, serial-safe on SQLite), lease + fencing tokens + heartbeats, cooperative cancellation, a `process_one` runner, and the job control API (`GET /jobs/{id}` snapshot, cancel, retry) — `backend/app/worker/`, `backend/app/api/v1/jobs.py`
- **Corpus calibration harness** (§19.1–19.2, §25.3 #3): the measurement apparatus that turns the two *measured* accuracy limits (grant printed-line precision, callout yield) into evidence-gated numbers instead of guesses — `backend/app/eval/`, `backend/corpus/`. A ground-truth **label schema** (`labels.py`, JSON-loadable so a corpus grows as data), pure **§19.1 metrics** (`metrics.py` — reference exact/±1, box IoU, callout precision/recall, association precision + zero-silent-verified invariant, wrong-document substitution rejection), a **golden harness** (`harness.py`) that aggregates by pooled counts and gates against the §19.2 release targets, and a **threshold calibration sweep** (`calibrate.py`) that reports a metric curve so a value is chosen from data (demonstrated on `alignment_min_ratio` — coverage vs 100% wrong-document rejection, which flags that the current 0.72 default would substitute a near-duplicate patent's text and evidence recommends 0.95). Runs in CI on a **synthetic seed corpus** (`cases.py`, no PDF/OCR libs or copyrighted PDFs); real labeled patents drop into `corpus/*.json`. CLI: `python -m app.eval.run` scores the seed corpus **plus any verified `corpus/*.json` labels** (`corpus.py` extracts each labeled PDF from `$XRAY_CORPUS_PDF_DIR`, folds it into the aggregate, and reports — not fails — labels whose PDF/artifact is unavailable; unreviewed scaffolds are skipped), non-zero exit on any failed gate. A **scaffold generator** (`scaffold.py`, `python -m app.eval.scaffold <pdf> --doc-id …`) pre-fills a label file from an extraction run so labeling is bootstrap-then-correct rather than transcription (procedure in `corpus/LABELING.md`). The two limits get real numbers once ≥20–30 real scans are labeled (§19.1); the framework is what makes that calibration, not tuning-by-eye.
- **SSE progress + resume** (§10.2, §10.6–10.7): live progress and resumable extraction. *Progress* — each meaningful transition advances a durable, monotonically increasing `progress_sequence`; `GET /jobs/{id}/events` streams the authoritative snapshot over Server-Sent Events using that sequence as the event id, honors `Last-Event-ID` on reconnect (a monotonic snapshot supersedes what was missed), and closes on a terminal state — polling `GET /jobs/{id}` stays the fallback. *Resume* — the extraction worker is checkpoint-aware (`app/worker/extraction.py`, `checkpoints.py`): the two §10.7 checkpoint kinds (`source_ready` preflight + per-page `page_text`) are persisted as `JobCheckpoint` rows keyed by source hash + engine + config + schema; a retry/superseding attempt reuses valid page checkpoints (skipping their OCR, and the PDF parse entirely when every page is cached), recomputes only what's missing, then **recomputes the fast downstream pipeline fresh**. A stale cache key invalidates cleanly; checkpoints are purged with the document.
- **Restricted-egress fetch processor** (Phase 2, §11.2/§17.4): an SSRF-hardened downloader (`app/fetch/`) — https + host-allowlist + DNS→IP public-only checks **re-run on every redirect** (anti-rebinding), byte/time/redirect caps, PDF magic-byte validation — plus a Google Patents `citation_pdf_url` resolver; the `fetch_source` processor turns `fetching_source` jobs into stored PDFs. The worker routes fetch jobs through it.
- **Extraction core** (Phase 3, §12.3–12.5): the clean-room, deterministic, geometry-anchored engine (`app/extraction/`) — an abstract page/word model, line grouping by adaptive baseline, centre-gutter line-number detection (multiples of five, OCR-repaired, cleaned to an arithmetic progression) with a piecewise `y→line` map shared across both columns, printed-column-number + header detection, two-column split, and `Entry` assembly (grant `col:line` + normalized box + source text) — ~98-99% exact vs. the reference engine. Decoupled from the PDF library (thin pdfplumber adapter). **Per-page OCR fallback** (pypdfium2 render + Tesseract `tessdata_best` via `app/extraction/ocr.py`) now performs background/edge cleanup, bounded projection-profile deskewing, separate left/right specification-column passes, and confidence-gated multi-pass recognition (Sauvola first, then alternate segmentation/adaptive Otsu and a binarized fallback only for weak text) while mapping every word box back to original PDF coordinates. It feeds the *same* line-reconstruction with confidence + `extraction_method="ocr"`; pages route native-vs-OCR by text-layer presence (native / ocr / hybrid mode). **Application publications** (`app/extraction/applications.py`) reconstruct by inline `[0001]` paragraph markers into `ApplicationLocator`s — the second document type through the same pipeline — with grant-vs-application **auto-detection** by marker density. Plus atomic artifact publication (§9.2) and the `extraction_processor` (passing the document's type) wired into the worker.
- **Figures + callouts** — the differentiator (Phase 3, §12.6–12.7). *Text side* (`app/extraction/figures.py`): figure references (`FIG. 3`, `FIGS. 4–6`, `12A`, `3A–3C`) with range/list expansion, and reference numerals (`housing 104`, coordinated `104 and 106`) with exclusions (claim numbers, years, measurements, `column:line`, figure IDs). *Drawing side* (`app/extraction/callouts.py`): drawing-page classification, per-page figure detection, and callout-numeral extraction with 400-DPI sparse-text OCR at 0°/90°/180°/270°, coordinate restoration, and confidence-first deduplication. **Mention→callout association** remains conservative: `verified` / `probable` / `ambiguous` (chooser) / `unresolved`, with figure context resolving ambiguity and never a silent guess (Q20). Remaining callout-yield tuning is corpus-driven (§19), not fitted to one patent.
- Tests: auth (401/403), the **IDOR matrix** (cross-user access → 404), upload/fetch/import/delete lifecycles, the patent + portable-save validators, the worker engine + job API, the fetch adapter + SSRF guard, and the **extraction algorithm** (line grouping, line-number detection, two-column split, OCR TSV parsing, application paragraph tagging + doc-type detection, figure/numeral detection, callout detection + verified/ambiguous/unresolved association), **clean-text alignment** (fuzzy per-line alignment, identity verification, provider parsing), the **enrichment stage wired into the worker** (aligns on verified identity; degrades gracefully on disabled/no-identity/fetch-failure/mismatch), the **SSE progress stream** (durable-sequence events, `Last-Event-ID` resume, owner-scoped, terminal close), **checkpoint-based resume** (first-run checkpointing, full/partial resume, stale-cache-key recompute), and the **golden-harness metrics + calibration** (reference exact/±1, box IoU, callout precision/recall, substitution rejection, evidence-based threshold sweep), the **per-document job endpoint** (`GET /documents/{id}/job`, owner-scoped), the **Alembic baseline** (applies cleanly + zero model drift), the **corpus label scaffold** (pre-fills references/callouts/associations from an artifact; loads back through the label schema) and **corpus auto-loading** (verified-only filtering; scores resolvable labels, skips the rest), the **security-header + rate-limit middleware** and **readiness probe** (DB + storage reachability), + publication — `backend/tests/` (**196 passing** (+ 28 frontend Vitest), `ruff` clean; frontend `tsc`/`vite build` verified, live SSE progress bar verified in-browser)
- **Clean-text alignment** (Phase 3, §13): `app/enrichment/` aligns noisy OCR to Google Patents' authoritative HTML text — sets `display_text` to the clean version **without overwriting `source_text`**, rejecting per-line substitutions below a confidence threshold (a monotonic cursor keeps it in sync). Plus identity verification (`verified`/`probable`/`mismatch`/`insufficient` — mismatch *blocks* alignment) and provider-text parsing. **Verified live**: parser extracts the 296 K-char clean description from the real page; on a real OCR'd page it located the text (ratio 1.00) and aligned 51/123 lines, unmatched lines safely keeping their OCR source. **Wired into the worker** (§13, `extraction_processor` → `_enrich_artifact`): after extraction and before publication, the pipeline fetches the provider page (restricted egress), verifies identity, and aligns the artifact's `display_text`, recording `identity_status` + `aligned_lines` in the artifact quality. It is best-effort — a disabled instance, a missing patent identity, a fetch failure, or an identity mismatch each falls back to the unaligned artifact so extraction still publishes.

**Verified live on a real scanned patent (`US12262260B2`):** the fetch adapter downloads it end-to-end; patentimages PDFs are **image-only scans** (0 text chars), so OCR is mandatory for the fetch path. OCR quality is excellent (Tesseract, ~95% word confidence → §23 #2 leans "Tesseract is enough"), and **two-column separation works** (columns no longer merge). Printed **`col:line` accuracy is now at parity with the reference engine** — ~98-99% exact / ~100% within one line, measured on 8 real grants (`backend/app/extraction/native.py`): line numbers are read from the printed centre gutter (multiples of five, OCR-repaired, cleaned to a regular arithmetic progression), the two columns share that one numbering by y-row, the printed column numbers set the true column numbers + the header cutoff, and a page with no gutter and no column pair is skipped as front matter. The extraction engine (§12–13) is now feature-complete in breadth: grants (native+OCR, two-column), applications (paragraphs), figures/callouts, and clean-text alignment, with the durable worker spine now complete: SSE progress and checkpoint-based resume (§10.2/§10.6–10.7). The **golden-harness + calibration framework** (§19) is in place and green on a synthetic seed corpus, and the **live progress bar is wired end to end** — the documents list streams each active job's stage and percentage over SSE and flips the row to ready on completion (verified live). The schema is now migration-managed: an **Alembic baseline** (`migrations/versions/`) creates the full §7 schema and is drift-checked against the models in CI. **Phase 4** (citation + viewer completion) is essentially done — citation profiles, search (scoped) / outline (sections + claims + figures + bookmarks + notes) / deep-links, server-persisted bookmarks/annotations, callout overlays + forward/reverse cross-navigation + an ambiguity chooser with **persisted mention→callout overrides** (§7 `ReferenceLinkOverride`), PDF zoom/rotation, quality/provenance surfacing, and portable exports. **Phase 5** (production hardening) is underway on the code-level items: strict **security-response headers** and a best-effort per-replica **rate limiter** (`backend/app/middleware.py`), a real **readiness probe** (`GET /ready` checks DB + object store, `503` when either is down), CI **dependency/supply-chain scanning** (`pip-audit` + `npm audit`) with **CycloneDX SBOMs**, an operations **[RUNBOOK.md](RUNBOOK.md)** (rehearsed backup/PITR restore, deletion-audit drill, secret rotation, egress posture, incident quick-reference), a **[SECURITY.md](SECURITY.md)** threat-model/disclosure doc, and an **accessibility + responsive pass** (verified in-browser): the specification is now a **keyboard-navigable listbox** (arrow/Home/End select and reveal lines, `aria-activedescendant`), **reference-numeral mentions are real buttons** (Enter/Space activate numeral→callout), the confidence dot no longer leaks onto every line's accessible name, and the viewer **no longer scrolls horizontally on mobile** (toolbar/citation actions wrap, container grid track capped). Still ahead: the one genuinely non-code task — labeling ≥20–30 real scanned patents into `corpus/*.json` for real §19.1 numbers (scaffold generator + `corpus/LABELING.md` make it a review pass) — plus **AT-specific** screen-reader testing and cross-browser (Safari/Firefox) verification, and the operational launch steps (provider deployment, canary engine versions).

## Stack (DESIGN.md §25)

| Layer | Choice |
|---|---|
| Language | Python |
| Backend | FastAPI (async, Pydantic validation, OpenAPI) |
| Frontend | React + TypeScript SPA (Vite); types generated from the backend OpenAPI schema |
| Data access | SQLAlchemy 2.0 (async) + Alembic |
| Auth + managed services | Supabase — Auth (JWT), managed Postgres (PITR), object storage |
| PDF rendering | PDF.js (client) |
| OCR | Tesseract (pending corpus measurement; DESIGN.md §23 #2) |

**Supabase integration rule:** the FastAPI service is the *only* database client — verify Supabase JWTs, connect to Postgres by connection string. Do **not** use Supabase's client-direct / RLS / PostgREST pattern; every query carries a server-side owner predicate (DESIGN.md §17.1).

## Local development

Backend:

```bash
cd backend
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
uvicorn app.main:app --reload
pytest
```

Frontend:

```bash
cd frontend
npm install
npm run dev
```

Copy `backend/.env.example` to `backend/.env` and fill in Supabase credentials before running against a database.
